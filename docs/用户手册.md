## 1. 简介

### 1.1 软件定位

**MC模组代码工作台**是一款纯 C# 打造的一站式 Minecraft 模组与整合包集成开发环境（IDE），覆盖模组开发从设计、编码到测试的完整闭环：

> 像素级纹理设计 → 可视化配方编辑 → 3D 多方块结构 → 代码编写 → 一键构建 → 游戏内测试

除了传统编码工作流之外，工作台还内置地图编辑、地牢编辑、红石/实体模拟、光影与渲染特效编辑等可视化设计工具，让不熟悉 Gradle 与 JSON 格式的创作者也能产出规范的资源包、数据包与整合包。

主界面共提供 **14 个功能模块**，分为五组：

| 分组 | 模块 |
|------|------|
| 设计 | 物品图像设计、AI 图像生成、配方设置、多方块结构设计、地图编辑、地牢编辑 |
| 编码 | 代码编写、开发环境 |
| 资源 | 资源导入 |
| 调试与模拟 | 测试工具、模拟运行 |
| 视觉 | 光影编辑、渲染编辑 |

另有「项目总览」首页，用于查看项目状态与快速打开最近项目。

### 1.2 系统要求

| 项目 | 最低要求 | 推荐配置 |
|------|----------|----------|
| 操作系统 | Windows 10 及以上（64 位） | Windows 11 |
| 处理器 | Intel Core i5 同级及以上 | i7 / Ryzen 7 |
| 内存 | 8 GB | 16 GB |
| 显卡 | GTX 1050 同级（需支持 DirectX 11，3D 视口与光影预览） | GTX 1660 及以上 |
| 运行时 | .NET 8 Desktop Runtime | 与应用同版本 |
| 磁盘空间 | 500 MB（不含 JDK / Gradle 缓存） | 2 GB |

如需执行真实 Gradle 构建，还需本机安装对应版本的 **JDK**（Java 8 / 17 / 21，随 Minecraft 版本而定）与 **Git**（可选，用于版本控制集成）。

## 2. 安装与启动

### 2.1 构建应用

本机 .NET SDK 若安装在非默认路径（例如 `D:\dotnet`，未加入 PATH），请在仓库根目录使用完整路径构建：

```powershell
D:\dotnet\dotnet.exe build MCModCoder.sln
```

构建成功后，主程序位于：

```
src\MCModCoder.App\bin\Debug\net8.0-windows\McModCoder.exe
```

### 2.2 启动步骤

由于 .NET SDK 安装在自定义目录，运行时需先设置 `DOTNET_ROOT` 环境变量，否则程序找不到 `hostfxr.dll` 会启动失败。在 PowerShell 中：

```powershell
$env:DOTNET_ROOT = "D:\dotnet"
& "src\MCModCoder.App\bin\Debug\net8.0-windows\MCModCoder.exe"
```

> 💡 若不想每次手动设置，可将两条命令保存为 `.ps1` 或 `.bat` 启动脚本。

### 2.3 界面总览

启动后主窗口（默认 1440×880，最小 1200×700）分为四个区域：

| 区域 | 说明 |
|------|------|
| **顶部标题栏** | 左侧为应用标识「MC模组代码工作台 v1.0」；右侧依次为项目信息文字（未打开项目时显示「未打开项目」，打开后显示 `项目名 · MC版本 · 加载器`）和三个按钮：**新建项目**、**打开项目**、**关闭** |
| **左侧导航栏** | 「功能模块」标题下的 **14 个单选导航项**，按 设计 / 编码 / 资源 / 调试与模拟 / 视觉 分组排列 |
| **中央内容区** | 当前选中模块的工作界面 |
| **底部状态栏** | 左侧显示操作反馈（如「就绪」「结构已保存：…」），右侧显示实时时钟 |

启动时默认进入「项目总览」。若检测到最近项目，状态栏会提示「就绪 — 检测到 N 个最近项目，可在项目总览中快速打开」。

### 2.4 未打开项目的守卫提示

除「项目总览」外，**所有模块都要求先创建或打开项目**。未打开项目时点击任意模块导航，将自动跳回项目总览，并在状态栏提示：

> 请先创建或打开一个项目（右上角「新建项目」）。

各模块内的具体保存 / 导出操作也有二次守卫，未打开项目时会弹出「请先打开项目。」提示框。

## 3. 项目管理

### 3.1 新建项目向导

有两种方式进入向导：

1. 点击主窗口右上角 **「新建项目」** 按钮——会自动切换到「开发环境」模块的「新建项目向导」标签页；
2. 直接在左侧导航进入「开发环境」→「新建项目向导」标签页。

向导表单字段如下：

| 字段 | 说明 | 默认值 |
|------|------|--------|
| **项目名称** | 模组显示名，同时决定主类名 | `MyMod` |
| **Mod ID** | 模组标识（小写）。修改项目名称后建议同步调整，配方 ID、资源包命名空间等都会使用它 | `mymod` |
| **Minecraft 版本** | 下拉选择，见 3.2 版本矩阵 | — |
| **模组加载器** | 随所选 MC 版本**级联过滤**，只列出该版本可用的加载器；旁边实时显示所需 Java 版本（如「Java: 17」） | — |
| **Java 包名** | 生成 Java 源码的包路径 | `com.example.mymod` |
| **作者** | 写入 mods.toml / fabric.mod.json | 空 |
| **描述** | 多行文本框 | 空 |
| **项目目录** | 项目根目录，可点击 **「浏览…」** 选择 | — |

填写完成后点击 **「创建项目并生成脚手架」**（宽按钮，高亮显示）。工作台会自动生成 `build.gradle`、`mods.toml` / `fabric.mod.json` 等完整脚手架，并创建项目文件 `<项目名>.mcmproj.json`。

### 3.2 支持的版本矩阵

选择 Minecraft 版本后，「模组加载器」下拉框会自动级联为该版本支持的加载器，Java 版本标签同步刷新：

| Minecraft 版本 | 可用加载器 | 所需 Java | 数据包 pack_format |
|----------------|------------|-----------|--------------------|
| 1.12.2 | Forge、Rift | Java 8 | 3 |
| 1.16.5 | Forge、Fabric | Java 8 | 6 |
| 1.18.2 | Forge、Fabric | Java 17 | 8 |
| 1.19.4 | Forge、Fabric | Java 17 | 13 |
| 1.20.1 | Forge、Fabric、NeoForge | Java 17 | 15 |
| 1.20.4 | Forge、Fabric、NeoForge | Java 17 | 26 |
| 1.20.6 | NeoForge、Fabric | Java 21 | 41 |

### 3.3 打开与关闭项目

- **打开项目**：点击右上角 **「打开项目」**，在文件对话框中选择 `.mcmproj.json` 文件（默认定位到最近项目所在目录）。
- **最近项目**：「项目总览」页面的「最近项目」列表中，每项显示项目名与路径，点击右侧 **「打开」** 按钮即可快速载入。
- **关闭项目**：点击右上角 **「关闭」** 按钮，回到未打开项目状态。

### 3.4 项目内 workspace 目录约定

创建项目后，工作台在项目目录下维护统一的 `workspace` 目录，各模块的产出自动落位：

```
<项目目录>\
├── <项目名>.mcmproj.json     项目配置文件
├── workspace\
│   ├── textures\             物品图像设计保存的纹理 PNG
│   ├── recipes\              配方 JSON（与数据包格式双向兼容）
│   ├── structures\           3D 结构设计保存的结构 (*.mcstructure.json)
│   ├── maps\                 地图编辑保存的地形 (*.mcmap.json)
│   ├── dungeons\             地牢编辑保存的布局
│   ├── shaders\              光影编辑保存的配置
│   ├── effects\              渲染编辑保存的粒子/材质/动画 JSON
│   ├── remote\               资源导入：mods（远程模组）/ packs（整合包安装包）/ modpacks（导入产物）
├── resourcepack\             生成资源包的输出目录（可再压缩为 zip）
├── modpack\                  整合包打包输出目录
└── src\ ...\                 Java 源码脚手架
```

## 4. 模块操作指南

以下逐一介绍全部 14 个功能模块（4.12「资源导入」属侧边导航「资源」分组，4.13「AI 图像生成」属侧边导航「设计」分组）。所有模块按钮文案均以界面实际显示为准。

### 4.1 物品图像设计

像素级纹理绘制器，界面分左（工具）、中（画布+预览）、右（图层+导出）三栏。

#### 4.1.1 图层系统（右侧「图层」面板）

- **新建 / 删除 / 重命名**：点击面板顶部一排按钮操作当前选中图层，重命名会弹出输入对话框。
- **显隐**：图层列表中每项左侧有复选框，勾选显示、取消隐藏。
- **上下移动**：点击 **「上移」/「下移」** 调整叠放次序；另有 **「合并」** 按钮向下合并。
- **透明度**：拖动「图层透明度」滑杆（0~100），数值实时显示在旁。
- 单击列表项切换当前编辑图层；每项还显示图层名称与尺寸信息。

#### 4.1.2 绘制工具（左栏「工具」区）

单选按钮组：**铅笔**（默认）、**橡皮**、**油漆桶（区域填充）**、**吸管（取色）**。

- **笔刷大小**：滑杆 1~16 px。
- **颜色**：色块显示当前色，旁边文本框可直接输入十六进制色值（如 `#FF6B6B`）；下方调色板可快速点选常用色。
- **对称绘制**：勾选 **「左右对称绘制」**，绘制时会自动在水平镜像位置同步落笔。
- **撤销 / 重做 / 清空图层**：工具区下方三个按钮。

#### 4.1.3 画布操作（中部）

- 顶部工具条：**缩放** 滑杆（0.25×~40×，默认 16×）、**「网格」** 复选框显示/隐藏网格线、右侧实时坐标显示「坐标：x, y」与画布尺寸「宽 × 高」。
- **鼠标操作**：左键或右键按住均可绘制（右键为绘制/擦除的对称操作），移动鼠标时坐标实时刷新。

#### 4.1.4 分辨率与自动适配

左栏「分辨率」区提供下拉框（16 / 32 / 64 / 128 / 256 / 512 / 1024）和 **「适配转换」** 按钮：

- 选择目标分辨率后点击按钮，画布内容自动缩放到新尺寸；
- 低清（≤16px）与高清（≥1024px）之间转换采用**最近邻插值**，保持像素风格不模糊。

#### 4.1.5 实时预览（画布下方）

三个单选项实时切换预览形态：

- **物品**：物品栏中的平面展示；
- **手持状态**：模拟第一人称手持角度；
- **放置状态**：模拟方块放置在地面上、带投影的立体效果。

#### 4.1.6 导出（右栏底部）

| 操作 | 步骤 |
|------|------|
| 导出图像 | 「导出格式」下拉选择 **PNG（推荐）/ JPEG / TIFF** → 点击 **「导出图像…」** → 选择保存路径 |
| 保存到纹理库 | 点击 **「保存到项目纹理库」**，输入纹理名后保存到 `workspace/textures/`（需已打开项目） |
| 生成资源包 | 点击 **「生成资源包结构…」**，输入资源名，自动生成含模型 JSON 的资源包目录并打包为 `resourcepack_<modid>.zip`，可直接放入 `.minecraft/resourcepacks` 使用 |

### 4.2 配方设置

可视化配方编辑器，界面分左（配方库）、中（编辑器）、右（验证+导入导出）三栏。

#### 4.2.1 配方列表（左栏）

- **分类过滤**：顶部下拉框，含 全部 / 常规 / 工具与武器 / 食物 / 矿物冶炼 / 建筑方块 / 魔法物品。
- **搜索**：文本框按 ID / 产物 / 分类关键字即时过滤，下方显示「N / M 个配方」。
- **新建**：创建一条配方，ID 自动按 `<modid>:new_recipe_N` 命名；**删除**：移除选中配方。
- 列表项显示配方 ID、类型（如「有序合成（合成台 3×3）」）与分类。

#### 4.2.2 拖拽式槽位编辑（中栏）

- 选中配方后，中栏按类型生成对应编辑界面（材料栏/槽位格、产物、烹饪时间、经验等字段）。
- 槽位支持**拖拽**：从中栏的材料面板按住左键拖动物品 ID 到目标槽位释放即可填入。
- 支持的配方类型：

| 类型 | 数据包 type 标识 |
|------|------------------|
| 有序合成（合成台 3×3） | `minecraft:crafting_shaped` |
| 无序合成 | `minecraft:crafting_shapeless` |
| 熔炉冶炼 | `minecraft:smelting` |
| 高炉熔炼（blasting） | `minecraft:blasting` |
| 烟熏（smoking） | `minecraft:smoking` |
| 切石机 | `minecraft:stonecutting` |
| 锻造台升级 | `minecraft:smithing_transform` |
| 酿造台（工作台扩展类型） | `mcmcoder:brewing` |

#### 4.2.3 验证与修正建议（右栏）

- 点击 **「验证当前配方」** 或 **「验证全部配方」**，结果列表逐条显示：
  - **徽标**（错误/警告级别）+ **消息** 描述问题；
  - 下方灰字给出**修正建议**（如缺少产物、材料为空等）。

#### 4.2.4 JSON 导入导出与数据包

| 按钮 | 功能 |
|------|------|
| **导入 JSON…** | 从文件导入数据包格式的配方 JSON |
| **导出 JSON…** | 将当前配方导出为 JSON 文件 |
| **批量导出数据包…** | 将全部配方导出为标准数据包（自动生成 `pack.mcmeta` 与 `data/<命名空间>/recipe/` 目录，pack_format 随项目 MC 版本） |
| **保存全部到项目** | 全部写入 `workspace/recipes/` |

> JSON 与 Minecraft 数据包格式双向兼容，可无缝对接真实游戏。

### 4.3 多方块结构设计

3D 体素结构编辑器，界面分左（调色板与操作）、中（3D 视口）、右（信息）三栏。

#### 4.3.1 方块调色板（左栏）

- **PaletteCombo 下拉框** 选择常用方块；也可在文本框输入自定义 ID（默认 `minecraft:stone`）后点击 **「添加」**。
- 当前选中方块即为放置用的"画笔"。

#### 4.3.2 3D 视口操作（中栏）

| 操作 | 效果 |
|------|------|
| **左键点击/拖动** | 放置当前方块 |
| **右键点击/拖动** | 删除方块 |
| **中键 或 Ctrl+左键拖动** | 旋转视角（自动切入自由视角） |
| **Shift+中键 或 Alt+左键拖动** | 平移视角（自动切入自由视角） |
| **滚轮** | 缩放（自动切入自由视角） |

- **视角预设**：左栏「视角预设」区可选 **全景**（默认 3/4 等轴）/ **俯视** / **侧视** / **正视**，切换时以约 0.5 秒的缓动动画平滑过渡（无生硬跳变）；选择 **「自由」** 后相机完全由你掌控（旋转/平移/缩放）。任何手动旋转、平移或缩放操作都会自动切入自由视角。
- 点击 **「重置」** 平滑过渡回全景视角；修改结构尺寸或加载新结构后，相机会自动平滑重新取景。
- 视口顶部工具条：**「新建」**（清空新建结构）、**「保存到结构库」**（存入 `workspace/structures/`，格式 `.mcstructure.json`）、**「加载…」**、**「生成放置指令」**（生成 `/place` 指令并自动复制到剪贴板，弹窗展示完整命令；在游戏中配合结构方块即可还原）。右侧实时显示结构信息。

#### 4.3.3 结构操作（左栏按钮组）

| 按钮 | 功能 |
|------|------|
| **绕Y轴旋转 / 绕X轴旋转 / 绕Z轴旋转** | 整体结构沿对应轴旋转 90° |
| **X轴镜像 / Z轴镜像** | 沿对应轴水平镜像 |
| **复制结构 / 粘贴结构** | 复制当前结构到内部剪贴板 / 粘贴 |
| **清空** | 清除全部方块 |

#### 4.3.4 结构尺寸

「结构尺寸」区输入 X / Y / Z 三向尺寸（默认 16×16×16），点击 **「应用尺寸」** 生效。右栏「已用方块」列表统计结构中各类方块的用量。

### 4.4 地图编辑

2D 俯视地形编辑器，界面分左（工具）、中（地图画布）、右（矿物配置）三栏。

#### 4.4.1 地形生成（左栏）

1. **种子**：文本框输入任意字符串（默认 `minecraft`）；
2. **基准高度**：滑杆 40~100（默认 64）；
3. **地形起伏**：滑杆 4~50（默认 20）；
4. **群系模式**：单选 **「按高度自动群系」** / **「温度带状群系」**；
5. 点击 **「生成地形」** 按钮（高亮），画布即按参数渲染彩色地形图。

#### 4.4.2 笔刷工具（左栏）

按住左键在画布上拖动即可雕刻：

| 笔刷 | 效果 |
|------|------|
| **提升** | 笔刷范围内地面升高 |
| **降低** | 范围内地面降低 |

#### 4.5.1 生成模式与参数（左栏）

#### 4.5.3 连通性检查与压力测试（右栏）

| 加载器 | 下拉：全部（默认）/ Forge / Fabric / NeoForge / Quilt |
| 排序 | 下拉：按相关性（默认）/ 按下载量 / 按更新时间 |
| **「加载更多」** | 追加下一页结果（每页 20 条）；没有更多时按钮置灰 |

**结果卡片**：左侧 40×40 项目图标（无图标时显示 📦 占位）；中间为项目名、作者（缺省「未知作者」）、**平台徽标**（Modrinth / CurseForge）、分类标签（最多 4 个）与两行简介；右侧为**下载量**——≥1 亿显示「x.x 亿」、≥1 万显示「x.x 万」，其余显示原值。

**详情面板**：点击任意卡片，页面底部展开详情面板——标题、**「⬇ 下载并解析依赖」** 按钮（仅模组项目显示）、元信息行（作者 · 下载量 · 更新日期 · 平台）、简介与文件列表（列：**版本号 / 游戏版本 / 加载器 / 大小 / 发布日期 / 操作**，按发布日期降序），点击 **「✕ 收起」** 折叠。

- **单文件下载**：点击文件行「操作」列的 **「下载」**（整合包项目为 **「下载整合包」**）加入下载队列。模组保存到 `workspace/remote/mods/`；整合包主文件保存到 `workspace/remote/packs/`，完成后状态栏会提示到【整合包导入】页选择该文件完成导入。
- **「⬇ 下载并解析依赖」**（仅模组）：按**项目设置**（「开发环境」中的 MC 版本与加载器，而非筛选栏当前选择）匹配最新主文件并解析依赖，全部文件（含主文件，按文件 ID 去重）一次性加入下载队列：
  - **Modrinth**：调用依赖接口，自动解析 **required** 依赖并**递归**解析依赖的依赖（深度上限 3 层，按项目 ID 去重防环）；
  - **CurseForge**：按主文件的 required 依赖列表逐个获取其最新文件（不再向下递归）。
  - 平台上没有匹配「项目版本 + 加载器」的文件时，会弹窗提示「未找到匹配 … 的文件版本」。

#### 4.12.2 整合包导入

左列为三张卡片，右列为「导入进度」卡片。

**① 本地导入**：点击 **「📂 选择整合包文件…」** 选择 `.mrpack` 或 `.zip` 文件，工作台自动识别格式：

| 文件类型 | 识别依据 | 解析方式 |
|----------|----------|----------|
| Modrinth `.mrpack` | 包内 `modrinth.index.json` | 本地解析索引，直接得到下载列表与 SHA1 |
| CurseForge `.zip` | 包内 `manifest.json` | 解析清单后**联网**逐个获取每个文件的下载信息 |

解析成功后显示信息卡（整合包名、MC 版本 · 加载器 · 来源、「需下载 N 个文件」或「无待下载文件（仅解压覆盖文件）」），点击 **「🚀 开始下载并导入」** 执行导入。

**② 已下载的整合包文件**：列出 `workspace/remote/packs/` 目录下的 `.mrpack` / `.zip`（按修改时间倒序），点击右侧 **「导入」** 可直接解析导入；在「资源搜索」页下载的整合包主文件也会出现在这里。

**③ 已导入的整合包**：导入记录列表（名称 + 「MC 版本 · 加载器 · 来源」），点 **「打开目录」** 在资源管理器中打开对应导入目录。

**导入流程**（点击「开始下载并导入」后自动执行）：

1. 逐文件下载到导入目录并做 **SHA1 校验**（进度条按「已完成文件数 + 当前文件进度」聚合，当前文件路径实时显示，并统计「已完成 N/M，失败 X」）；
2. 全部文件处理完后，把包内 `overrides/` 内容（mods、config 等）**解压覆盖**到导入目录；
3. 登记到「已导入的整合包」列表并保存历史记录。

**导入产物位置**：`workspace/remote/modpacks/<整合包名>/`，mods、config 等内容已就位，可直接作为实例目录使用。个别文件下载失败（如直链失效）不会中断导入：弹窗列出失败明细（最多展示 12 条），成功文件保留，重新解析并再次导入即可补齐。

#### 4.12.3 下载管理

集中查看与管理所有下载任务（模组与整合包共用一个队列，**并发下载 3 个**）。任务卡片显示名称、状态、进度条、目标文件名与大小；右侧操作按钮随状态变化：**重试**（失败/已取消）、**取消**（排队中/下载中/校验中）、**移除**（完成/失败/已取消）。顶部工具条：**「重试全部失败」**、**「清除已完成」**、**「📂 打开 mods 目录」**。

**任务状态与颜色**：

| 状态 | 颜色 | 说明 |
|------|------|------|
| 排队中 | 暗灰 | 已入队，等待空闲并发位 |
| 下载中 | 黄色 | 正在传输，进度条实时推进 |
| 校验中 | 黄色 | 下载完成，正在做 SHA1 校验 |
| 完成 | 绿色 | 文件已落盘且校验通过 |
| 失败 | 红色 | 鼠标悬停状态文字可查看错误原因，可「重试」 |
| 已取消 | 暗灰 | 手动取消，可「重试」 |

**SHA1 校验**：平台提供来源哈希的文件在下载完成后自动比对，**来源哈希不符会标记为失败**（提示「SHA1 校验失败：文件名（来源文件可能已更新）」），点击「重试」即可重新下载。下载先写入临时文件（`*.part`），校验通过后才改名就位，不会残留半截文件。

**单模组下载位置**：`workspace/remote/mods/`（「📂 打开 mods 目录」即打开该目录）。下载与导入历史按项目持久化在 `workspace/remote/` 下（`downloads.json` / `imports.json`），重启后自动恢复；因重启而中断的任务会标为失败，可手动重试。

#### 4.12.4 常见问题

**Q：CurseForge 搜索/下载失败，提示网络错误？**
CurseForge 默认走社区公益镜像 `api.curse.tools`（**无需 API 密钥**）；若镜像不可用，可由开发者在代码中将 `CurseForgeClient.ApiKey` 配置为官方 API 密钥，配置后自动切换官方接口 `api.curseforge.com`。Modrinth 始终走官方接口 `api.modrinth.com`。

**Q：提示「网络请求超时，请检查网络连接」？**
多为网络/代理波动。恢复网络后：搜索可直接重新点击「🔍 搜索」；下载任务在「下载管理」点「重试」（单次执行内部已自动重试 3 次，仍失败才标记失败）。

**Q：任务反复失败，错误为「SHA1 校验失败」？**
来源文件可能已被作者更新，平台哈希与实际下载不符。可先「重试」；仍失败则回到「资源搜索」详情面板改选其他版本文件。

**Q：整合包导入时部分文件下载失败？**
多为文件直链失效，成功文件已保留。可重新选择/解析该整合包并再次点击「🚀 开始下载并导入」，已就位文件会被覆盖补齐。

**Q：点击「资源导入」显示「尚未打开项目」？**
资源导入的所有产物都落到项目 workspace 内，需先创建或打开项目（右上角「新建项目」/「打开项目」）。

### 4.13 AI 图像生成

把**外接 AI 图像模型**接入工作台：用一句话描述生成物品图标、方块纹理、生物立绘等像素素材，弥补手工绘制效率不足。模块需联网（或访问本机 SD WebUI），并依赖项目上下文——未打开项目时整页显示「🔒 尚未打开项目」遮罩。

#### 4.13.1 外接服务设置（左栏上方）

| 控件 | 说明 |
|------|------|
| 服务类型 | **OpenAI 兼容接口**（DALL-E 及各类兼容网关）/ **Stable Diffusion WebUI** |
| 服务地址 | OpenAI 兼容填 `https://api.openai.com/v1`（自动补全 `/images/generations` 路径）；SD WebUI 填 `http://127.0.0.1:7860`（服务需以 `--api` 启动） |
| API 密钥 | OpenAI 兼容接口必填；SD WebUI 留空 |
| 模型 | 如 `dall-e-3`、`dall-e-2`、`cogview-3` 等（SD WebUI 忽略）。对 dall-e-2/3 会预校验尺寸（dall-e-3 仅支持 `1024x1024` / `1792x1024` / `1024x1792`），填错会在本地给出可读提示，而非服务端 400 报错 |
| 出图尺寸 | 下拉可选或直接输入，如 `1024x1024`、`512x512` |
| 负面提示词 | 不希望出现的内容：SD WebUI 以独立字段发送；**OpenAI 兼容接口会以「Avoid…」自动融入正向提示词**（该类接口不支持独立负面字段） |
| 像素风格约束 | 勾选后自动附加「pixel art game texture…」风格后缀（内含 no text / no watermark 等防干扰指令）。选「方块纹理」等**无缝平铺**类风格时会自动省略「纯色背景」指令，避免自相矛盾导致出图不稳定（推荐开启） |

点击 **「💾 保存设置」** 持久化（保存在 `%APPDATA%\MCModCoder\ai-image.json`，全局共享、不属于单个项目）。API 密钥仅保存在本机。

#### 4.13.2 生成与导入（左栏下方 + 右栏）

1. 在文本框输入图像描述（如「一把发光的蓝色魔法剑，剑身缠绕闪电」），可点击**风格预设**（物品图标 / 方块纹理 / 生物怪物 / 工具武器 / 食物 / 附魔符文）附加对应提示词；
2. 点击 **「🎨 生成图像」**，生成期间按钮置灰、状态实时提示；提示词会先经过**本地审计**（空提示词、超长、占位符残留等直接拦截，不发起网络请求）；
3. 生成结果**先过输出审计再决定是否保存**（见 4.13.3）：通过后自动保存到 `workspace/ai-images/` 并在右栏大图预览（DALL-E 3 会额外显示模型改写后的提示词）；**未打开项目时仅预览不落盘**；
4. **「📥 导入到纹理库」**：导入前会**再次审计**——存在错误直接阻止；存在警告（如画面疑似纯色）弹窗确认后才复制到 `workspace/textures/` 并推送给「物品图像设计」模块；
5. **「生成历史」**缩略图列表（按时间倒序，最多 60 张）点击即可重新预览并查看该图审计结论；点击预览大图可另存为；**「📁 打开所在文件夹」**直达 ai-images 目录。

#### 4.13.3 生成结果审计（可靠性门禁）

每次生成返回后，右栏预览下方会出现**审计面板**，对 AI 输出做确定性检查（相同数据必得相同结论）。结论分三级：

| 级别 | 含义 | 处理方式 |
|------|------|----------|
| ✘ 错误 | 数据无效或已损坏（非 PNG、传输截断、结构无法解析等） | **自动阻止保存与导入**，不会在项目目录产生脏文件 |
| ⚠ 警告 | 结果可能不符合预期（画面疑似纯色/空白、近全透明、尺寸与请求不符、数据校验和异常等） | 照常保存，但面板逐条给出建议；**导入纹理库时会弹窗要求确认** |
| ℹ 提示 | 事实性信息（尺寸、颜色数、非方形提示等） | 无需处理 |

常见警告与建议的对应关系：

- **`img.solid` 画面几乎为纯色**：多为模型未能按提示词渲染（提示词过于抽象、风格冲突）。按建议丰富描述或更换风格预设后重试；
- **`img.transparent` 近全透明**：在提示词中要求纯色背景，或使用负面提示词排除透明背景；
- **`img.size` 返回尺寸与请求不符**：部分服务会自行调整尺寸，可继续使用；需精确尺寸请生成后缩放；
- **`img.truncated` 数据被截断**：多为网络不稳定，直接重新生成即可（错误级，本次不会保存）。

审计同时覆盖**提示词**（长度超限、`{{占位符}}` 残留、控制字符）与**代码片段**（括号配对、占位符残留），同一套结论模型贯穿「生成 → 保存 → 导入」全流程，规则详见 [API文档.md](API文档.md) §2.5.12。

#### 4.13.4 常见问题

**Q：提示「外接 AI 服务返回 401/403」？**
API 密钥缺失或无效，检查密钥与账户额度。

**Q：SD WebUI 连不上？**
确认以 `--api` 参数启动（`webui-user.bat` 中加 `set COMMANDLINE_ARGS=--api`），地址填 `http://127.0.0.1:7860`。

**Q：生成的图不像 MC 纹理？**
保持勾选「像素风格约束」，并选择匹配的风格预设；提示词中可补充「16x16 sprite」「top-down」等关键词。

**Q：审计面板报「画面几乎为纯色」，但图片看起来正常？**
审计按颜色占比判定（≤3 种颜色且主色 ≥99% 触发）。低对比度的简单图案可能命中——确认为想要的图后，在导入确认弹窗选「是」即可正常入库；若想反馈误判，可检查提示词是否缺少细节描述。

**Q：为什么这次生成的图没有保存到项目目录？**
审计发现错误级问题（如数据截断、非 PNG）时会阻止落盘，避免脏文件混入 `workspace/ai-images/`。查看审计面板中的 ✘ 条目按建议重试即可；历史列表中也看不到它，属正常行为。

## 5. 模块间数据流转

各模块并非孤岛，数据通过项目 `workspace/` 目录与导出机制无缝衔接，形成闭环：

### 5.1 地牢 → 3D 结构

```
地牢编辑（生成/手动布局） → 「推送到 3D 结构设计器」 → 多方块结构设计（3D 精修）
                                                       → 「保存到结构库」 → 「生成放置指令」
```

地牢布局被自动转换为多层方块结构（按墙体/地板材质填充、走廊镂空），在结构设计器中可继续旋转、镜像、增删方块。

### 5.2 纹理 → 资源包 → 整合包

```
物品图像设计（绘制完成）
  → 「保存到项目纹理库」→ workspace/textures/*.png
  → 「生成资源包结构…」→ resourcepack/ 目录 + resourcepack_<modid>.zip（含模型 JSON）
  → 开发环境「📦 打包整合包」→ modpack/（自动收纳纹理生成资源包）
```

### 5.3 配方 → 数据包 → 构建

```
配方设置（编辑+验证）
  → 「保存全部到项目」→ workspace/recipes/*.json
  → 「批量导出数据包…」→ 标准数据包（pack.mcmeta + data/<ns>/recipe/）
  → 开发环境「🔨 一键构建」（processResources 阶段打包资源）
  → 开发环境「📦 打包整合包」（自动收纳配方生成数据包）
```

### 5.4 构建 → 测试 → 部署

```
开发环境「🔨 一键构建」→ build/libs/<modid>-1.0.0.jar
  → 测试工具「部署模组（复制到 mods）」或热重载自动部署
  → 启动游戏 → 测试工具「导入日志…」+「🧠 智能分析」定位问题
  → 回到代码编写修改 → 再构建（热重载自动重新部署）→ 循环迭代
```

### 5.5 其他衔接点

- **光影编辑 / 渲染编辑**的配置保存在 `workspace/shaders/` 与 `workspace/effects/`，效果 JSON 可「复制 JSON」后直接粘贴进代码编辑器使用；
- **代码编写**的片段库会按当前项目自动替换 `{{modid}}`、`{{package}}` 等占位符；
- **模拟运行**可用于验证红石装置与实体行为设计，再回到地图/结构模块落实。

## 6. 常见问题 FAQ

### Q1：双击 exe 提示找不到 `hostfxr.dll`，无法启动？

**原因**：.NET 运行时安装在自定义目录（如 `D:\dotnet`），系统找不到 .NET 宿主。

**解决**：启动前先设置环境变量（PowerShell）：

```powershell
$env:DOTNET_ROOT = "D:\dotnet"
& "src\MCModCoder.App\bin\Debug\net8.0-windows\MCModCoder.exe"
```

或将两条命令保存为启动脚本。也可将 `D:\dotnet` 加入系统 PATH 后直接双击运行。

### Q2：点击模块提示「请先创建或打开一个项目」？

这是**预期行为**：除「项目总览」外，全部功能模块都依赖项目上下文。请先点击右上角「新建项目」完成向导，或「打开项目」/ 在项目总览的「最近项目」列表中快速载入。

### Q3：「🔨 一键构建」日志里出现"未检测到 gradlew.bat，执行内置模拟构建流程"？

首次创建的项目不含 Gradle Wrapper，工作台执行模拟构建以验证流程。要真实构建：

1. 本机安装与项目匹配的 JDK（见 3.2 版本矩阵）；
2. 在项目目录执行 `gradle wrapper` 生成 `gradlew.bat`；
3. 重新点击「🔨 一键构建」。

若真实 Gradle 构建报错，请查看构建日志中的 `[stderr]` 行：常见问题包括 JDK 版本不匹配（换用项目设置中指定的 Java 版本）、依赖下载超时（检查网络/配置镜像）、`build.gradle` 被手动修改后与项目设置不一致（在「项目设置与依赖」重新保存即可重新生成）。

### Q4：部署时提示「未找到构建产物」？

「测试工具」的部署依赖 `build/libs/<modid>-1.0.0.jar`。请先到「开发环境 → 构建与打包」执行一次构建，再回来部署。模拟构建也会生成该产物。

### Q5：像素画布放大后鼠标移动卡顿？

将「缩放」滑杆适当调低，或在超大分辨率（512/1024）下编辑时关闭「网格」显示。分辨率转换（「适配转换」）瞬间完成，不影响后续绘制性能。

### Q6：地牢压力测试显示"部分种子存在孤立房间"？

将左栏「环路连接概率」滑杆调高（如 0.3 以上）重新生成，或在「走廊连接模式」中手动补一条走廊。

### Q7：AI 补全浮窗频繁弹出干扰输入？

在「代码编写」工具条取消勾选 **「AI 辅助补全」** 即可关闭补全浮窗；取消勾选右栏「AI 开发助手 → 启用」可关闭实时建议与内容点评；需要时再勾选恢复。两项开关彼此独立、可任意组合。

### Q8：性能方面有什么使用建议？

- 3D 结构与光影/渲染预览同时开多个会占用较多 GPU，建议用完一个模块再切换下一个；
- 渲染编辑中「最大粒子数」超过 1000 且开启加法混合时，低端显卡可能掉帧，可参考「⚡ 性能建议」面板的提示调参；
- 测试工具的性能监控本身开销极小，可常开观察游戏进程的 CPU / 内存曲线；
- 代码编辑器对超过 30 万字符的文件自动停用语法高亮以保证输入流畅，属正常现象。

### Q9：配方 JSON 能否直接给真实游戏用？

可以。导出的 JSON 与 Minecraft 数据包格式双向兼容，「批量导出数据包…」生成的目录含 `pack.mcmeta`（pack_format 自动匹配项目 MC 版本），可直接作为数据包放入存档或世界 `datapacks/` 目录使用。

## 8. 智能辅助功能（v1.1 新增）

v1.1 围绕"检索更快、编写更顺、选择更准、下载更稳、命名更规范"五个方向，为工作台增加了一批智能辅助能力。所有功能入口均融入原有界面，无需额外学习成本。

### 8.1 全局快速搜索（Ctrl+K）

主窗口标题栏右侧新增搜索框（快捷键 **Ctrl+K** 随时聚焦），支持对以下内容的关键词即时检索与定位：

- **功能模块**：输入模块名或别名（如"配方""红石""下载"）直接跳转对应模块；
- **项目资产**：即时检索项目工作区内的纹理、配方、结构、地图、地牢、光影、特效文件（文件名与内容均参与匹配）；
- **源码行级定位**：检索 `src/main/java` 下的 Java / JSON / GLSL 源码，命中结果直接显示匹配行摘要。

操作方式：输入即搜（160ms 去抖），**↑/↓** 选择候选，**Enter** 打开，**Esc** 关闭弹窗。

- 点击**模块**类结果 → 自动切换到对应模块；
- 点击**文件**类结果 → 自动跳转模块；代码类结果还会在代码编辑器中打开该文件并**选中定位到具体行**（状态栏提示"已定位：…（第 N 行）"）。

结果不足时，搜索弹窗会自动附加以「AI 推荐」标记的关联词条，点击即按推荐词重新检索（见 8.4）。

### 8.2 编辑器内查找与增强代码补全（代码编写模块）

- **编辑器内查找**：快捷键 **Ctrl+F** 打开右上角查找栏，输入关键词即时显示"N 个结果"，**Enter / ↓** 下一个、**Shift+Enter / ↑** 上一个，匹配项自动选中并滚动到可视区，**Esc** 或 **✕** 关闭。**F3 / Shift+F3** 在关闭查找栏后仍可继续跳转最近一次的搜索。
- **AI 辅助补全增强**（工具条「AI 辅助补全」开关保持不变）：
  - 在原有 Forge / Fabric 上下文规则之外，新增**文档词库补全**——自动扫描当前文件中出现的全部标识符（类名、变量名、方法名），按"前缀匹配优先 + 出现频次"排序给出候选，详情显示"文档标识符 · 出现 N 次"；
  - 上下文规则建议与词库候选自动合并去重，前缀命中者排在最前，补全更贴合你正在编写的代码；
  - 新增**语句级预测**：光标位于空行时，浮窗给出"预测下一句"建议（事件起手取实体、服务端保护包裹、注册条目模板、JSON 配方骨架等，详见 4.6.2），与词级补全互补。

### 8.3 AI 开发助手（代码编写模块，右栏）

编辑器右侧「🤖 AI 开发助手」面板提供三类能力（右栏「启用」开关控制，全程本地分析、不联网）：

- **实时建议**：结合代码内容与最近操作（插入片段 → 检查占位符残留；格式化 → 检查括号配对；保存/打开 → 文件名与类名一致性等）给出分级提示（⚠ 建议修复 / 💡 优化 / ℹ 提醒）；
- **内容点评**：0-100 综合评分 + 一句话总结 + ✨ 亮点与 🔧 可改进清单，评分徽标按分数着色；
- **语句预测**：见 8.2。

与全局搜索的 AI 推荐条目（见 8.4）互不影响。

### 8.4 AI 智能匹配推荐

内置 Minecraft 模组生态知识库（食物 / 科技 / 存储 / 魔法 / 性能优化 / 世界生成 / 地牢结构等常用主题），基于模糊评分算法（前缀 > 包含 > 子序列 + 词元重叠）自动推荐关联内容：

- **资源导入页**：筛选栏下方新增「🤖 AI 智能推荐」词条行，依据当前项目上下文（项目名 / ModID / 描述 / MC 版本 / 加载器）生成，鼠标悬停显示推荐理由，点击词条立即按该关键词搜索；
- **全局搜索**：结果较少或为空时自动追加 AI 推荐词条，点击即按推荐词检索；
- **项目总览**：未打开项目时全局搜索亦可使用，推荐词条随项目切换自动刷新。

### 8.5 下载时自动匹配项目版本（资源导入模块）

筛选栏右侧新增 **「⤓ 自动匹配项目版本」** 复选框（默认开启）。下载模组文件时，工作台会先检测所选文件的游戏版本与加载器是否与当前项目匹配：

- **不兼容时自动匹配**：后台查询该模组在「项目 MC 版本 + 项目加载器」下的最新兼容文件，弹窗展示兼容版本信息，确认后自动替换下载（状态栏提示"已自动匹配项目版本并加入下载队列"）；
- **找不到兼容版本**：明确提示所选文件可能不兼容，由你决定是否仍要下载，避免装错版本导致游戏崩溃；
- **匹配过程失败**（如网络波动）不阻断下载，自动回退为按所选文件下载。

「下载并解析依赖」流程原本就按项目设置匹配版本，不受此开关影响。

### 8.6 上传 / 保存时自动命名

所有需要输入名称的保存入口，现在都会**依据文件内容或元数据预生成规范统一的名称**（输入框中可自由修改）：

| 入口 | 自动命名依据 | 名称示例 |
|------|--------------|----------|
| 物品图像设计 → 保存到项目纹理库 | 画布尺寸 + 图层名 + 主色（内容签名哈希）+ ModID，目录内自动去重 | `mymod_tex_16x_a1b2c3` |
| 物品图像设计 → 生成资源包结构 | 与纹理库同一签名，保证命名一致 | `mymod_tex_16x_a1b2c3` |
| 代码编写 → 将选中代码存为片段 | 代码内容分析（类名 / 方法名 / 首个关键调用），无法识别时回退内容哈希 | `ExampleEvents_onRightClickBlock` |
| 光影编辑 → 保存配置 | ModID + 日期，目录内自动去重 | `shader_mymod_20261001` |
| 多方块结构设计 → 保存到结构库 | 结构名 + 同名冲突自动追加序号 | `MyStructure_2` |
| 地牢编辑 → 保存 | 地牢名 + 同名冲突自动追加序号 | `dungeon_2` |

同名文件不再被静默覆盖：冲突时自动追加 `_2`、`_3`… 序号并保存在状态栏提示中说明。
