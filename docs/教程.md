# MC模组代码工作台 · 新手教程

> 本教程面向第一次接触 Minecraft 模组开发的新手，所有按钮文案、界面布局、文件格式均与当前版本的「MC模组代码工作台 v1.0」一致。跟随六篇教程走完，你将体验从**画纹理 → 配配方 → 搭结构 → 写代码 → 构建 → 测试发布**的完整闭环。

---

## 开始之前：准备与主界面

### 启动程序

本工作台是 WPF 桌面应用（.NET 8，Windows）：

1. 打开 PowerShell，进入项目根目录 `d:\code\demo1\mc-mod-coder`；
2. 构建解决方案：`D:\dotnet\dotnet.exe build MCModCoder.sln`；
3. 设置运行时目录并启动：

```powershell
$env:DOTNET_ROOT = "D:\dotnet"
& "src\MCModCoder.App\bin\Debug\net8.0-windows\MCModCoder.exe"
```

### 认识主界面

窗口标题为 **「MC模组代码工作台 — Minecraft 模组与整合包集成开发环境」**，从上到下分三块：

- **顶部标题栏**：左侧是logo与「MC模组代码工作台 v1.0」；右侧依次为项目状态（如 `MyMod · 1.20.1 · Forge`，未打开时显示「未打开项目」）和三个按钮：**「新建项目」「打开项目」「关闭」**。
- **左侧导航栏**：分四组共 12 个模块——
  - **设计**：物品图像设计 / 配方设置 / 多方块结构设计 / 地图编辑 / 地牢编辑
  - **编码**：代码编写 / 开发环境
  - **调试与模拟**：测试工具 / 模拟运行
  - **视觉**：光影编辑 / 渲染编辑
  - （最上方还有一个「项目总览」，显示项目状态卡与最近项目列表。）
- **底部状态栏**：显示操作反馈（如「已打开项目：MyMod（1.20.1 / Forge）」）与时间。

> 💡 **小贴士**：还没有打开项目时，点击任何设计/编码模块都会被拦下，状态栏会提示 *「请先创建或打开一个项目（右上角「新建项目」）。」*——这是有意设计的流程保护。点「新建项目」会自动跳到「开发环境」模块的向导页。

### 项目与 workspace 目录约定

项目本质是一个 JSON 文件：`<项目名>.mcmproj.json`，保存在你指定的项目目录中。项目一旦打开（新建或通过「打开项目」选择 `.mcmproj.json`），工作台会自动在项目目录下创建以下 workspace 工作区：

```
我的项目/
├─ MyMod.mcmproj.json        ← 项目元数据（名称/ModID/版本/加载器/依赖等）
├─ workspace/
│  ├─ textures/  recipes/  structures/
│  ├─ maps/      dungeons/ shaders/  effects/
└─ src/main/java/…           ← 生成的 Java 源码
```

最近打开的项目记录在 `%APPDATA%\MCModCoder\recent.json`（最多 8 个），可在「项目总览」中一键「打开」。

## 教程一：从零创建第一个模组（开发环境模块）

> **你将学会**：用新建项目向导生成完整可构建的 Forge/Fabric 工程；认识脚手架里的关键文件；在代码编辑器中使用片段库、AI 补全、格式化与静态检查；一键构建并把产物部署到游戏 mods 目录。

### 1. 走一遍新建项目向导

1. 点击右上角**「新建项目」**（或左侧导航进入「开发环境」模块，选中**「新建项目向导」**页签），标题为「创建 Minecraft 模组工程」。
2. 填写表单（从上到下）：
   - **项目名称**：默认 `MyMod`，改成 `RubyMod`。Mod ID 会自动同步为小写下划线形式（如 `rubymod`）；一旦手动修改过 Mod ID，就不再自动跟随。
   - **Mod ID**：模组的注册命名空间，只能小写字母/数字/下划线。它决定资源路径 `assets/<modid>/…` 与配方路径 `data/<modid>/…`。
   - **Minecraft 版本**：下拉可选 1.12.2 / 1.16.5 / 1.18.2 / 1.19.4 / 1.20.1 / 1.20.4 / 1.20.6，默认 1.20.1。
   - **模组加载器**：随版本联动（1.12.2 → Forge/Rift；1.16.5~1.19.4 → Forge/Fabric；1.20.1/1.20.4 → Forge/Fabric/NeoForge；1.20.6 → NeoForge/Fabric）。旁边的 `Java: 17` 标签会提示该版本所需 JDK 主版本（1.12.2/1.16.5 → 8；1.20.6 → 21；其余 → 17）。
   - **Java 包名**：默认 `com.example.<modid>`，作为主类的 package。
   - **作者 / 描述**：会写入 mods.toml / fabric.mod.json。
   - **项目目录**：留空则默认创建在 `文档\MCModCoder\<项目名>`；也可点**「浏览…」**选择文件夹（自动追加子目录 `<项目名>`）。
3. 点击**「创建项目并生成脚手架」**。若目录非空会弹窗确认。完成后弹窗显示「项目「RubyMod」创建成功！共生成 N 个文件。」，日志里还给出下一步建议（画纹理 → 配配方 → 写代码 → 部署运行）。

> 💡 **小贴士**：之后若改了项目设置（「项目设置与依赖」页签 → 改完点**「保存设置」**），脚手架配置文件会按新设置重新生成，你手写的源码不会被覆盖。

### 2. 认识生成的工程结构

生成的文件清单会打印在向导页日志中。不同加载器关键文件不同：

**Forge（1.16.5 ~ 1.20.4）与 NeoForge：**

| 文件 | 作用 |
|---|---|
| `build.gradle` | ForgeGradle 构建脚本：`group = '<你的包名>'`、`archivesName = '<modid>'`、Java 工具链、`minecraft { mappings channel: 'official' … }`（1.17+ 用 official 映射）、依赖 `minecraft "net.minecraftforge:forge:1.20.1-47.3.0"`、以及你在依赖管理中添加的依赖 |
| `gradle.properties` / `settings.gradle` | JVM 内存参数、mod_id 等属性与插件仓库配置 |
| `src/main/java/<包路径>/<主类>.java` | 主类，`@Mod(<主类>.MODID)` 标注，构造函数里订阅 Mod 事件总线 |
| `src/main/resources/META-INF/mods.toml` | 模组元数据：modId、displayName、authors、description，以及 `[[dependencies.<modid>]]` 对 forge/minecraft 的版本要求 |
| `src/main/resources/pack.mcmeta` | 内嵌资源包描述（`pack_format` 随 MC 版本自动填，如 1.20.1 为 15） |

**Forge 1.12.2 特有**：使用 ForgeGradle 5.1.+ 与 `stable_39` 映射、Java 8、依赖固定 `1.12.2-14.23.5.2859`；元数据是 `src/main/resources/mcmod.info`（JSON 数组格式）；主类用 `@Mod.EventHandler` 的 preInit/init 生命周期。

**Fabric：**

| 文件 | 作用 |
|---|---|
| `build.gradle` | `fabric-loom` 插件，依赖 minecraft / yarn 映射 / `fabric-loader:0.15.11` / `fabric-api:0.97.8+1.20.1` |
| `src/main/resources/fabric.mod.json` | 入口声明：`"entrypoints": { "main": ["<包名>.<主类>"] }`，以及 `depends`（fabricloader、minecraft、java、fabric-api 版本范围） |
| 主类 | `implements ModInitializer`，注册逻辑写在 `onInitialize()` |

另外所有工程都会生成 `.gitignore`（忽略 `build/`、`run/`、`.gradle/` 等）。主类名由项目名称推导：非字母数字字符替换为 `_`，数字开头自动补 `_`。

### 3. 用代码编辑器写第一段代码

1. 进入左侧导航**「代码编写」**模块。顶部工具条有：**「新建」「打开…」「保存」「格式化」**，右侧是 **「AI 辅助补全」** 复选框（默认勾选）与 **「Git 状态」「Git 提交…」**。
2. 点**「打开…」**选中刚生成的主类（或「新建」一个 `.java` 文件），当前文件名会显示在工具条中。
3. **插入片段**：左侧「代码片段库」提示 *「双击插入到光标处」*。找到 **「Forge 注册物品」**（DeferredRegister 注册物品的模板）双击，光标处即插入：

   ```java
   public static final DeferredRegister<Item> ITEMS =
           DeferredRegister.create(ForgeRegistries.ITEMS, MODID);

   public static final RegistryObject<Item> RUBY =
           ITEMS.register("ruby",
                   () -> new Item(new Item.Properties().stacksTo(64)));
   ```

   片段库还内置「Forge 主类 / Forge 注册方块 / Fabric 入口 / 事件监听 / 合成配方 JSON / 物品模型 JSON / 光源方块 GLSL」。选中一段自己的代码后点左下**「将选中代码存为片段」**可保存为自定义片段（持久化在 `%APPDATA%\MCModCoder\snippets.json`）。
4. **体验 AI 补全**：在 `new Item(new Item.Properties()` 后停顿，编辑器旁弹出「AI 补全建议 (Enter 确认 / Esc 关闭)」列表，例如 `stacksTo(64)`（最大堆叠数）、`durability(250)`、`fireproof()`、`rarity(Rarity.EPIC)`。用 ↑↓ 选择、**Enter/Tab** 确认，Esc 关闭。补全是上下文感知的：`level.`、`player.`、`Item.Properties().` 等触发不同建议；不需要时取消勾选「AI 辅助补全」即可完全关闭。
5. **格式化与静态检查**：写乱缩进后点**「格式化」**（统一 4 空格缩进）。下方错误面板实时做轻量静态检查——括号不匹配、`package` 语句缺分号、`class` 声明后缺 `{` 等，正常时显示「✔ 无静态检查问题」。`Ctrl+S` 快速保存。

> 💡 **小贴士**：AI 补全是本地知识库实现的（不联网），它认识 Forge/Fabric/1.12.2 三套 API 的常见写法，还能在编辑 JSON 配方时补全 `"type": "minecraft:crafting_shaped"` 这类字段值。

### 4. 一键构建与产物部署

1. 进入**「开发环境」→「构建与打包」**页签，点**「🔨 一键构建」**：
   - 项目里有 `gradlew.bat`（真实工程）时，执行 `gradlew build --console=plain --parallel`，Gradle 输出实时滚动到日志区；
   - 没有 Wrapper 时执行内置模拟构建（configure → compileJava → processResources），日志会打印 `> 生成：<项目目录>\build\libs\<modid>-1.0.0.jar`。
2. 构建产物位置：**`<项目目录>\build\libs\<modid>-1.0.0.jar`**。
3. 勾选**「构建后启动游戏客户端」**可在构建后拉起 runClient（需已配置 Forge/Fabric 运行环境）。
4. **部署测试**：切到**「测试工具」**模块（详见教程六），把 jar 复制到游戏 mods 目录即可进游戏验证；也可点**「📦 打包整合包（资源+数据+模组清单）」**把纹理资源包、配方数据包、模组清单一起输出到 `<项目目录>\modpack\`。顶部的**「🚀 部署到测试环境」**按钮会提示你使用「测试工具」模块完成热重载部署。

> 💡 **小贴士**：推荐工作流——写代码 → 「🔨 一键构建」→ 测试工具里开热重载，构建产物一变化就自动复制进 mods 目录，重启游戏即可看到改动。

## 教程二：设计一个物品纹理并生成资源包（物品图像设计模块）

> **你将学会**：16×16 像素画的基本操作（铅笔/油漆桶/吸管/对称/撤销）；图层管理与分辨率转换；三种实时预览；导出 PNG、保存到纹理库、一键生成可直接放进游戏的资源包。

### 1. 画一个 16×16 的低清纹理

1. 进入左侧导航**「物品图像设计」**。左侧工具栏默认选中**「铅笔」**，其余工具：**「橡皮」「油漆桶（区域填充）」「吸管（取色）」**。
2. 画布默认 16 × 16（右上角显示 `16 × 16`），缩放滑杆默认 16×，勾选**「网格」**方便对齐像素；移动鼠标时工具条显示当前坐标。
3. 在「颜色」区点色块或直接输入十六进制值（默认 `#FF6B6B`），下方调色板可快速选常用色。**笔刷大小**滑杆 1~16 px。
4. 勾选**「左右对称绘制」**，画一半自动镜像另一半——画对称的宝石/剑刃特别省事。
5. 画错点**「撤销」**，画过头点**「重做」**，**「清空图层」**重画当前层。油漆桶用于大面积填底色，吸管从画面取色。

> 💡 **小贴士**：原版物品纹理就是 16×16，低清反而是“像素风”的正确打开方式；先用大色块铺底，再加 1px 高光和暗部。

### 2. 图层与分辨率转换

1. 右侧「图层」面板有六个按钮：**「新建」「删除」「重命名」「上移」「下移」「合并」**（合并 = 向下合并）。每个图层前有可见性复选框，「图层透明度」滑杆 0~100%。
2. 练习：图层 1 画底色，新建图层 2 画高光，把图层 2 透明度降到 60% 做柔光效果。
3. **分辨率转换**：左下「分辨率」下拉选 `32 / 64 / … / 1024`，点**「适配转换」**。所有图层按最近邻插值缩放（状态栏提示 *「分辨率已转换为 1024×1024（最近邻插值，像素风保持）。」*）。低清（≤16px）与高清（≥1024px）之间互转都不会糊边。

> 💡 **小贴士**：转换是不可回退的大改动（撤销栈也会清空），转换前先把 16×16 原稿「导出图像…」留档。

### 3. 三种实时预览

画布下方是**「实时预览：」**区，三个单选项随时切换：

- **「物品」**：带阴影的悬浮图标（背包里看到的样子）；
- **「手持状态」**：倾斜 -28° 的手持透视效果；
- **「放置状态」**：等距立方体三面贴图（顶面/左面/右面不同明暗），适合方块纹理。

### 4. 导出 PNG / 存入纹理库 / 一键生成资源包

右下「导出」区三个按钮，从轻到重：

1. **「导出图像…」**：格式下拉选 **「PNG（推荐）」**（或 JPEG/TIFF），保存到任意位置。
2. **「保存到项目纹理库」**：弹出「纹理名称（不含扩展名）」输入框（如 `ruby`），保存为 `workspace/textures/ruby.png`，并自动推送一条消息给「渲染编辑」模块共享使用。
3. **「生成资源包结构…」**：输入纹理名称后，工作台自动生成完整资源包到 `<项目目录>\resourcepack\`，并压成 `resourcepack_<modid>.zip`。目录结构：

```
resourcepack/
├─ pack.mcmeta                                  ← pack_format 按你的 MC 版本自动填写
├─ pack.png
└─ assets/<modid>/
   ├─ textures/item/ruby.png                    ← 你的纹理
   └─ models/item/ruby.json                     ← 自动生成的物品模型
```

其中 `models/item/ruby.json` 内容为：

```json
{ "parent": "item/generated", "textures": { "layer0": "<modid>:textures/item/ruby" } }
```

> 💡 **小贴士**：生成的 zip 可直接放入 `.minecraft/resourcepacks` 启用；若你在做模组，把 `assets/<modid>/` 整个目录拷进 `src/main/resources` 即可随模组 jar 发布。开发环境里「📦 打包整合包」也会自动把纹理库中的 PNG 按同样规则收进 `modpack/resourcepack`。

## 教程三：给物品添加配方并导出数据包（配方设置模块）

> **你将学会**：用 3×3 拖拽网格创建有序合成；切换熔炉/切石机等类型；看懂验证器的错误/警告；把配方批量导出为 Minecraft 数据包。

### 1. 新建配方并拖拽摆槽

1. 进入左侧导航**「配方设置」**。左栏「配方库」点**「新建」**，自动生成 ID `<modid>:new_recipe_1`（左侧列表可看到 Id、类型与分类）。
2. 中栏编辑器从上到下：**「配方类型」**下拉（有序合成（合成台 3×3）/ 无序合成 / 熔炉冶炼 / 高炉冶炼 / 烟熏炉 / 篝火烹饪 / 切石机 / 锻造台升级 / 酿造台）、**配方 ID**、**分类**（默认「常规」，可改成「工具与武器」等，也可自定义）。
3. 保持默认「有序合成（合成台 3×3）」，在下方**「物品面板（拖拽到格子 / 点击后点击格子）」**中按住 `iron_ingot` 拖进 3×3 网格顶部一行，`stick` 拖进中列下方两格（经典镐子形状）。点击已填的格子可清除内容。
4. **key 字母自动推导**：你不需要手写 pattern/key——同一物品自动分配同一字母（A、B、C…与 `#`），空格留白。底部产物栏填产物 ID 与数量（如 `minecraft:iron_pickaxe` ×1，也可填自定义 ID 如 `rubymod:ruby_pickaxe`）。

### 2. 切换其他配方类型

在**「配方类型」**下拉里切换，编辑器会随之变化：

- **熔炉冶炼/高炉冶炼/烟熏炉/篝火烹饪**：变成单个**「输入材料 ingredient」**输入框 + **「烧炼时间与经验」**（cookingtime 刻 / experience，熔炉默认 200 刻、0.1 经验）；
- **切石机**：输入材料 + 产物数量（count）；
- **锻造台升级**：锻造模板 template（可选）/ 基础物品 base / 附加材料 addition 三栏；
- **酿造台**：酿造材料 ingredient / 底酒 base（如 `minecraft:potion`）/ 酿造时间。

材料框中既可以填原版 ID（`minecraft:iron_ore`），也可以填标签（`#minecraft:planks`，井号开头表示标签）或你自己的物品 ID。

### 3. 验证与修正

右栏「配方验证」区点**「验证当前配方」**，问题分三级显示，每条附带**修正建议**：

- **✖错误**：如图案中字符未在 key 定义、产物为空、各行长度不一致、无序合成超过 9 项等——不修无法正常工作；
- **⚠警告**：如 ID 缺少命名空间前缀（建议 `mymod:xxx`）、产物数量超过 64、锻造配方缺 template 等；
- **ⓘ提示**：如「高炉默认耗时为 100 刻」等平衡性建议。

点**「验证全部配方」**批量汇总（「全部 N 个配方验证完成：错误 X 个，警告 Y 个。」）。改动槽位时会自动重新校验。

### 4. 保存与批量导出数据包

1. **「保存全部到项目」**：把所有配方写入 `workspace/recipes/<配方路径>.json`（项目内格式，外层带分类信息）：

   ```json
   {
     "app": { "category": "工具与武器", "description": "" },
     "recipe": { "type": "minecraft:crafting_shaped", "...": "数据包格式正文" }
   }
   ```

2. **「批量导出数据包…」**：选择输出目录，生成**可直接放入存档 `datapacks/` 的完整数据包**：

   ```
   你选的目录/
   ├─ pack.mcmeta                     ← { "pack": { "pack_format": 15, "description": "由MC模组代码工作台生成的配方数据包" } }
   └─ data/<modid>/recipe/<配方名>.json   ← 每个配方一个文件
   ```

   `pack_format` 由所选 MC 版本自动决定（1.12.2→3、1.16.5→6、1.18.2→8、1.19.4→13、1.20.1→15、1.20.4→26、1.20.6→41）。
3. 单个配方也可用**「导出 JSON…」/「导入 JSON…」**与别人交换（导入的配方分类自动记为「导入」）。

**导出的 JSON 与原版数据包完全同构**，几个实际例子（由序列化器真实输出）：

有序合成（key 值为字符串，物品或 `#` 标签；count 为 1 时省略）：

```json
{
  "type": "minecraft:crafting_shaped",
  "pattern": [ "AA ", " B ", " B " ],
  "key": {
    "A": "minecraft:iron_ingot",
    "B": "minecraft:stick"
  },
  "result": { "item": "minecraft:iron_pickaxe" }
}
```

熔炼：

```json
{
  "type": "minecraft:smelting",
  "ingredient": "minecraft:iron_ore",
  "cookingtime": 200,
  "experience": 0.7,
  "result": { "item": "minecraft:iron_ingot" }
}
```

切石机（result 直接是物品字符串）：

```json
{
  "type": "minecraft:stonecutting",
  "ingredient": "minecraft:stone_bricks",
  "count": 2,
  "result": "minecraft:stone_brick_slab"
}
```

> 💡 **小贴士**：导入导出是双向兼容的——把网上找的原版配方 JSON「导入 JSON…」即可继续可视化编辑。唯一例外是酿造台：工作台导出为扩展类型 `mcmcoder:brewing`（原版没有酿造数据包格式），需要配套模组运行。1.19.4+ 原版把 recipe 目录从 `recipes` 改名 `recipe`，工作台始终输出新目录名，配新版本存档即可。

## 教程四：多方块结构与地牢（多方块结构设计 + 地牢编辑）

> **你将学会**：3D 视口的放置/删除/旋转/缩放；调色板与旋转镜像复制；生成 `/place template` 指令；用随机参数生成地牢、做连通性压力测试，并把地牢推送进 3D 结构设计器继续打磨。

### 1. 3D 视口基本操作（多方块结构设计）

进入左侧导航**「多方块结构设计」**，中间是 3D 视口。左侧面板顶部写着操作口诀：

> **左键放置 · 右键删除 · 中键/Ctrl+左键 旋转视角 · 滚轮缩放**

1. 「方块调色板」下拉选择方块（默认调色板含石头、泥土、橡木板、玻璃、砖块、铁/金/钻石块、萤石、水等），也可在文本框输入任意 ID（如 `rubymod:ruby_block`）点**「添加」**加入调色板。
2. 视角区可在**「第三人称 / 第一人称」**间切换，点**「重置」**回到初始机位。
3. 「结构尺寸」X/Y/Z 默认 16×16×16，改小（如 5×5×5）后点**「应用尺寸」**更容易上手。

### 2. 结构操作与放置指令

1. 「结构操作」八宫格：**「绕Y轴旋转」「绕X轴旋转」「绕Z轴旋转」「X轴镜像」「Z轴镜像」「复制结构」「粘贴结构」「清空」**。旋转按 90° 步进（Y 轴旋转 4 次回到原样），「复制结构」后可在「粘贴结构」时得到 `<名称>_副本`。
2. 视口顶部工具条：**「新建」「保存到结构库」「加载…」「生成放置指令」**。
3. **「保存到结构库」**写入 `workspace/structures/<结构名>.mcstructure.json`，格式为「调色板 + 坐标索引」：

   ```json
   {
     "Name": "RubyAltar",
     "SizeX": 5, "SizeY": 5, "SizeZ": 5,
     "Palette": [ "minecraft:air", "minecraft:stone", "minecraft:gold_block" ],
     "Blocks": { "0,0,0": 1, "2,1,2": 2 }
   }
   ```

4. 点**「生成放置指令」**，弹出并复制指令到剪贴板：

   ```mcfunction
   /place template mymod:ruby_altar ~ ~ ~
   ```

   （名字自动小写、空格转下划线。）在游戏中用结构方块保存同名结构后即可用该指令放置。右侧「已用方块」列表实时统计结构中用到的方块。

### 3. 生成一座地牢（地牢编辑）

进入左侧导航**「地牢编辑」**，左栏是生成规则，中间是俯视预览画布（房间 + 走廊连线）。

1. 「生成模式」保持**「随机生成」**；点 **🎲** 按钮换一个随机种子。
2. 调参数：**房间数量**（3~30，默认 10）、**房间尺寸**（默认 7~15）、**走廊宽度**（1~7，默认 3）、三个房间类型复选框（**「包含宝物房」「包含刷怪房」「包含 BOSS 房」**）、**环路连接概率**（0~0.6，默认 0.15——调高可减少死胡同）、**墙体**（默认 `minecraft:bricks`）与**地板**（默认 `minecraft:stone_bricks`）。
3. 点**「生成地牢」**，画布上出现房间与走廊，右侧房间列表显示每间房的类型；选中房间可直接拖拽挪位置。
4. 想手工布局？切到**「固定结构（手动布局）」**：用**「添加房间」**放新房、点**「走廊连接模式」**后依次点击起点房→终点房连线、**「删除选中」**移除。**「保存…」「加载…」**存取到 `workspace/dungeons/`。

### 4. 连通性检查与压力测试

右栏「测试生成」区：次数框默认 20，点**「× 次压力测试」**，工作台用不同随机种子连续生成 N 次，并用并查集做连通性检查，输出报告：

```
压力测试结果（20 次）：
─────────────────────
平均房间数：10.4
最少 / 最多：8 / 13
全连通率：95%
─────────────────────
⚠ 部分种子存在孤立房间，建议提高环路连接概率。
```

连通率低就把「环路连接概率」调高再测，直到提示「✔ 生成器稳定。」

### 5. 推送到结构设计器跨模块流转

1. 点**「推送到 3D 结构设计器」**：地牢布局被转换为多层方块结构（地板层 + 4 层墙体 + 走廊镂空 + 顶部封顶，刷怪房放 `minecraft:spawner`、宝物房放 `minecraft:chest`、墙上点缀 `minecraft:torch`），并通过跨模块事件直接推入「多方块结构设计器」。
2. 切回**「多方块结构设计」**，刚才的地牢已在 3D 视口中——旋转视角检查走廊是否畅通，用左键/右键微调方块，再**「保存到结构库」**。

> 💡 **小贴士**：这条「地牢 → 结构」管线是本工作台模块协作的样板：俯视图管布局效率高，3D 视口管细节打磨，两步结合比单边硬肝快得多。

## 教程五：光影与粒子效果（光影编辑 + 渲染编辑）

> **你将学会**：调太阳角度/阴影/雾并拍快照 A/B 对比；导出 GLSL uniforms；用发射器调一团火焰；调材质球金属度/粗糙度；给粒子尺寸挂动画曲线；并按性能建议控制开销。

### 1. 光影编辑：调光、拍快照、导出 GLSL

1. 进入左侧导航**「光影编辑」**，右侧是实时 3D 预览场景，左侧从上到下四组参数：
   - **光源设置**：太阳高度角（0~90）、太阳方位角（0~360）、光照强度（0~2）、太阳颜色（`#FFF3D6`）；
   - **阴影效果**：阴影强度（0~1）、阴影柔化；
   - **环境光**：环境光强度（0~1）、环境光颜色（`#8FA6C8`）；
   - **雾效**：雾密度（0~0.08）、雾颜色；另有**「体积光（God Rays 预览提示）」**与**「ACES 色调映射」**复选框、emissive 自发光增益（0~3）。
2. **快照 A/B 对比**：调参前点**「📷 快照 A」**，调完再点**「📷 快照 B」**，两张缩略图并排放在预览上方，前后差异一目了然。
3. 点**「导出 GLSL 配置…」**保存 `shader_config.glsl`。文件把你的参数换算成可直接粘贴进光影包的 uniforms（太阳方向由角度算出单位向量）：

   ```glsl
   uniform vec3  sunDirection   = vec3(-0.5000, 0.7071, -0.5000);
   uniform float sunIntensity   = 1.00;
   uniform float shadowStrength = 0.60;
   uniform float fogDensity     = 0.0150;
   ...
   vec3 applyFog(vec3 color, float dist, float worldY) { ... }
   vec3 applyLighting(vec3 albedo, float ndl, float shadow) { ... }
   ```

4. **「保存配置」「加载配置」**把整套参数存为 `workspace/shaders/<名称>.mcshader.json`，随时复用。

### 2. 渲染编辑：调一团火焰

进入左侧导航**「渲染编辑」**，右侧大预览实时播放粒子（顶部显示 `FPS：`、`粒子数：`、`内存：`，可用 **「⏸ 暂停」「↺ 重置」**控制），左栏有**「粒子 / 材质 / 动画」**三个标签。

1. 在**「粒子」**标签中调成火焰：
   - **发射形状**选**「锥形」**（另有「点源」「环形」），扩散角 0.6 左右让火焰向上收拢；
   - **起始色 `#FFE066` → 结束色 `#FF5722`**：颜色沿生命周期从亮黄渐变到橙红；
   - 起始尺寸 4px → 结束尺寸 0.5px：火苗越烧越小；
   - 勾选**「加法混合（火焰/魔力发光）」**：粒子叠加发亮，是火焰/魔法的经典质感；
   - 发射速率 40 个/秒、生命周期 1.2 秒、重力 0.4、最大粒子数 600。
2. 在**「材质」**标签调**「材质参数」**：金属度（0~1，1 = 全金属反射）、粗糙度（0.05~1，越低高光越锐利）、自发光、基础色、**「渲染层（Render Type）」**（solid / cutout / translucent）、**「使用法线贴图」「使用高光贴图」**。画面右下角有材质球实时预览：高光锐度 = 1 − 粗糙度，金属度增强反射，自发光产生辉光。
3. 在**「动画」**标签给粒子挂曲线：勾选**「粒子尺寸随生命周期曲线变化」**，在「关键帧（t = 时间，v = 取值，均 0~1）」列表用**「＋ 添加」**输入 t/v 添加关键帧、选中后**「删除」**；拖动「采样 t =」滑杆可在曲线上取值检查。曲线启用后同时驱动预览中粒子的尺寸（默认曲线 1 → 0.8 → 0，即先慢缩后消失）。
4. **保存与复用**：**「保存效果 / 加载效果」**读写 `workspace/effects/<名称>.mceffect.json`（一次打包粒子+材质+动画三份配置）；**「复制 JSON」**把当前配置复制到剪贴板；**「打开效果目录」**直达 workspace/effects。
5. 点**「⚡ 性能建议」**，右上弹出体检报告，例如：
   - 「最大粒子数 > 800：中端 GPU 上可能掉帧，建议 ≤ 600。」
   - 「发射速率 × 生命周期超过最大数量，实际粒子会被截断：调大 MaxCount 或降低速率。」
   - 「半透明层 + 非加法混合需要逐粒子排序，建议改用 cutout 或开启加法混合。」
   - 通用结论：粒子越小越省填充率；加法混合适合火焰/魔力，烟尘用 alpha 混合。

> 💡 **小贴士**：教程二里「保存到项目纹理库」的纹理会被推送进本模块，可把自绘纹理与粒子/材质配置组合成完整的物品特效方案。

## 教程六：模拟、测试与发布（模拟运行 + 测试工具）

> **你将学会**：在红石模拟器里搭电路并用 Shift+点击操控拉杆/按钮；生成实体与改游戏规则；跑内置测试套件；导入游戏日志做智能分析；监控性能；最后打包整合包交付。

### 1. 红石电路模拟（模拟运行）

进入左侧导航**「模拟运行」**的**「⚡ 红石电路」**页签：

1. 左栏「方块选择」：**红石导线 / 红石火把 / 拉杆（点击切换）/ 按钮（脉冲）/ 红石灯 / 中继器 / 实心方块 / 橡皮擦**。
2. 画布上**左键放置**、**右键擦除**；关键交互：**Shift + 左键**点击已放置的**拉杆/按钮**——拉杆切换开关状态，按钮发出脉冲。勾选**「显示信号强度数字」**可在导线上看到 15 级衰减。
3. 点**「▶ 自动运行」**让模拟持续走刻（「模拟速度」滑杆 1~20），或用**「单步」**逐刻调试；**「清空」**重开。没有思路时点**「载入示例：非门/时钟电路」**，观察红石火把的反相与中继器的整流延时。

> 💡 **小贴士**：模拟规则与游戏一致——信号 15 级衰减、火把反相、中继器整流。用单步模式能看清每一刻的传播顺序，排查“为什么灯不亮”特别有效。

### 2. 实体模拟与游戏规则

切到**「🐕 实体与方块交互」**页签：

1. 点**「僵尸×5」「牛×5」「羊×5」**在画布生成实体，**「清空实体」**一键移除；点**「▶ 运行模拟」**开始逐刻模拟（**「重置」**停止复位）。
2. 「游戏规则」区勾选 `doDaylightCycle 昼夜循环`、`keepInventory 死亡不掉落`、`mobGriefing 生物破坏`；**「时间刻度（0-24000）」**滑杆拖到 18000 看夜晚；**「重力（玩家跳跃模拟）」**调到 0.5 体验低重力，点**「跳跃！（物理测试）」**观察弹道。画布底部实时显示当前规则状态。

### 3. 内置测试套件、日志分析与性能监控（测试工具）

进入左侧导航**「测试工具」**：

1. **跑内置测试**：左栏点**「▶ 运行内置测试套件」**，输出逐条 ✔/✖ 结果——覆盖配方 JSON 往返序列化、验证器、结构旋转/镜像变换、红石模拟（拉杆点亮灯、火把反相）、日志解析等，最后汇总「结果：N 通过，M 失败」。它验证的是工作台自身核心链路，适合在自定义修改后做回归检查。
2. **部署与热重载**：**「游戏 mods 目录」**默认 `%APPDATA%\.minecraft\mods`（可点 `…` 更改）；点**「部署模组（复制到 mods）」**把 `build/libs/<modid>-1.0.0.jar` 复制过去（没构建会提示先去「开发环境」构建）。勾选**「热重载：构建产物变化时自动重新部署」**后，状态显示「热重载已启用（监控 build\libs）」，之后每次构建产物更新都会 2 秒防抖后自动复制。**「打开日志目录…」**直达游戏的 `logs/`。
3. **日志智能分析**：右上点**「导入日志…」**选择 `latest.log` 或崩溃日志，可用级别筛选（全部/ERROR/WARN/INFO）与关键词搜索；点**「🧠 智能分析」**，下方列出诊断条目（标题 + 详情 + 绿色建议），能识别：游戏崩溃报告、空指针异常、注册对象未初始化、缺少必需依赖、客户端/服务端模组不一致、Mixin 注入失败、内存不足（建议 -Xmx ≥ 4G）、OpenGL 错误、模组重复加载等，并附「ERROR X 条 / WARN Y 条 / 共 N 行」统计。
4. **性能监控**：左下「性能监控」下拉框点**「刷新」**枚举本机游戏进程（如 `javaw (PID 12345)`），选好后点**「开始监控」**，顶部文本实时显示 `CPU: xx% | 内存: xxx MB | 预览帧率: --`，下方曲线图绘制历史走势。

### 4. 打包整合包与交付清单

发布前回到**「开发环境 → 构建与打包」**，点**「📦 打包整合包（资源+数据+模组清单）」**，输出到 `<项目目录>\modpack\`：

```
modpack/
├─ resourcepack/      ← workspace/textures 里所有 PNG 自动按 assets/<modid>/ 组织
├─ datapack/          ← workspace/recipes 里的配方编译为 data/<modid>/recipe/
└─ modlist.txt        ← 整合包清单：模组本体 jar、MC 版本/加载器、依赖坐标列表
```

交付前过一遍清单：

- [ ] `build/libs/<modid>-1.0.0.jar` 构建成功（「🔨 一键构建」日志末尾无 ✖）；
- [ ] 资源包：纹理 + item 模型齐备（教程二），进游戏 F3+T 不缺材质；
- [ ] 数据包：「验证全部配方」零错误（教程三）；
- [ ] 结构文件已保存到结构库，`/place template` 指令可放置（教程四）；
- [ ] 游戏日志「智能分析」无 ERROR 级条目（本教程）；
- [ ] `modlist.txt` 的依赖列表与「项目设置与依赖」一致，玩家按清单放齐依赖模组。

把 `modpack/` 整体压缩即可分发。

| 光影编辑 | 「📷 快照 A / 📷 快照 B」 | 调参前后各拍一张对比 |

## 附录 B：workspace 产物文件一览表

| 目录 | 产出模块 | 触发按钮 | 产物 |
|---|---|---|---|
